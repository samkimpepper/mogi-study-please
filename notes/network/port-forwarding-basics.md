# 🚪 포트 포워딩은 왜 할까?

> [!summary]
> 포트 포워딩은 **한 주소와 포트로 들어온 네트워크 요청을 실제 서버가 기다리는 다른 주소와 포트로 전달하는 규칙**이다.

---

## 🤔 처음 헷갈렸던 점

WSL2는 VM이라서 Windows와 실행 환경이 분리되어 있다. 그런데 WSL2에서 `pnpm dev`로 서버를 실행하면 Windows 브라우저의 `localhost`에서 접속할 수 있었다.

이때 포트 포워딩과 비슷한 네트워크 연결이 사용된다고 하는데, 포트 포워딩이 무엇이고 왜 필요한지 헷갈렸다.

---

## 🏢 먼저 포트가 무엇일까?

IP 주소는 네트워크에서 **컴퓨터를 찾는 주소**이고, 포트는 그 컴퓨터 안에서 **요청을 받을 프로그램을 구분하는 번호**다.

> IP가 건물 주소라면 포트는 건물 안의 호수와 비슷하다.

컴퓨터 한 대에서도 여러 서버 프로그램이 동시에 실행될 수 있다.

| 프로그램 | 흔히 사용하는 포트 |
| --- | ---: |
| 프론트엔드 개발 서버 | `3000` |
| Spring 애플리케이션 | `8080` |
| PostgreSQL | `5432` |
| Redis | `6379` |

다음 주소에서 IP와 포트는 서로 다른 역할을 한다.

```text
192.168.0.10:8080
──────────── ────
 컴퓨터 주소   프로그램의 입구
```

운영체제는 `8080`번 포트로 들어온 요청을 그 포트에서 기다리고 있는 서버 프로세스에 전달한다.

---

## ➡️ 포트 포워딩의 동작

`forward`는 전달한다는 뜻이다. 포트 포워딩 규칙은 다음과 같이 읽을 수 있다.

> “A 주소의 X 포트로 들어온 요청을 B 주소의 Y 포트로 보내라.”

```mermaid
flowchart LR
    C[클라이언트] -->|localhost:8080| E[접근 가능한 입구]
    E -->|포트 포워딩| S[실제 서버 172.30.10.5:3000]
    S -->|응답| E
    E --> C
```

사용자는 `localhost:8080`으로 접속하지만 실제 서버는 다른 네트워크 공간의 `3000`번 포트에서 실행될 수 있다.

```text
localhost:8080 → 172.30.10.5:3000
```

들어오는 포트와 전달받는 포트가 같을 필요도 없다. 중요한 것은 **외부에서 접근할 수 있는 입구와 실제 서버의 입구를 연결하는 것**이다.

---

## 🧭 왜 필요할까?

서버가 클라이언트가 직접 접근하기 어려운 네트워크 공간에 있을 때 사용한다.

- 서버가 WSL2 같은 VM 안에 있을 때
- 애플리케이션이 Docker 컨테이너 안에 있을 때
- 서버가 공유기 뒤의 사설 네트워크에 있을 때
- 외부에 보여줄 포트와 실제 서버 포트를 다르게 운영할 때

포트 포워딩이 없다면 사용자가 내부 서버의 IP와 포트를 직접 알아야 하거나, 네트워크 구조상 아예 접근하지 못할 수 있다.

백엔드 흐름으로 비유하면 Controller가 외부 요청을 받아 실제 Service에 넘기는 모습과 비슷하다.

```text
POST /orders                    localhost:8080
      ↓                               ↓
OrderController                 포트 전달 규칙
      ↓                               ↓
OrderService                    내부 서버:3000
```

둘이 같은 기술이라는 뜻은 아니고, **접근 가능한 앞쪽 입구가 실제 처리 대상으로 넘겨준다**는 흐름이 비슷하다는 뜻이다.

## 🐧 WSL2에서의 예시

Windows와 WSL2는 실행 환경이 분리되어 있으므로 각각의 `localhost`도 원칙적으로 자기 자신을 가리킨다.

```text
Windows의 localhost → Windows 자신
WSL2의 localhost    → WSL2 Linux 자신
```

그런데 WSL은 개발 편의를 위해 Windows에서 WSL2의 네트워크 애플리케이션으로 접근할 수 있도록 네트워크를 통합한다.

```text
Windows 브라우저
http://localhost:3000
          ↓
Windows · WSL 네트워크 연결
          ↓
WSL2 Linux에서 실행 중인 Node 서버
```

따라서 WSL2에서 `pnpm dev`를 실행한 뒤 Windows 브라우저의 `localhost`로 접속할 수 있다.

> [!info]
> WSL의 정확한 연결 방식은 NAT 또는 mirrored 같은 네트워크 모드에 따라 달라진다. 포트 포워딩은 이 동작의 핵심 목적을 이해하기 좋은 모델이지만, 모든 모드가 내부적으로 완전히 같은 방식으로 구현된다는 뜻은 아니다.

---

## 🐳 Docker에서의 예시

다음 명령은 호스트의 `8080`번 포트를 컨테이너의 `3000`번 포트와 연결한다.

```bash
docker run -p 8080:3000 my-app
```

`-p`의 값을 다음 순서로 읽으면 된다.

```text
-p 호스트_포트:컨테이너_포트
```

```text
브라우저의 localhost:8080
              ↓
Docker의 포트 연결
              ↓
컨테이너 내부 서버:3000
```

사용자는 `8080`으로 접속하지만 컨테이너 안의 애플리케이션은 계속 `3000`번 포트를 사용한다.

---

## 🌍 공유기에서의 예시

집 밖의 사용자가 공유기 안쪽의 서버에 접속하게 만들 때도 포트 포워딩을 사용한다.

```text
인터넷 사용자
      ↓ 공인 IP:8080
공유기
      ↓ 포트 포워딩
192.168.0.10:3000
      ↓
내부 서버
```

공유기는 외부 `8080`번 포트로 들어온 요청을 내부 컴퓨터의 `3000`번 포트로 전달한다.

> [!warning]
> 공유기의 포트를 외부에 열면 인터넷에서 서버에 접근할 수 있게 될 수 있다. 인증, 방화벽, 서버 보안과 노출 범위를 함께 확인해야 한다.

## 🧩 바인딩과 포워딩은 다르다

둘은 자주 함께 등장하지만 역할이 다르다.

| 개념 | 질문 | 하는 일 |
| --- | --- | --- |
| 바인딩 | 서버가 어디에서 요청을 받을까? | 서버 프로세스가 IP와 포트를 점유하고 대기 |
| 포트 포워딩 | 이 입구로 온 요청을 어디로 보낼까? | 받은 연결을 다른 IP와 포트로 전달 |

예를 들어 Node 서버가 컨테이너 안의 `0.0.0.0:3000`에 바인딩되고, Docker가 호스트 `8080`을 컨테이너 `3000`으로 전달할 수 있다.

```text
서버 바인딩: 컨테이너 안에서 3000번 포트를 열고 기다림
포트 포워딩: 호스트의 8080번 요청을 그 3000번으로 전달
```

서버가 외부 연결을 받을 수 없는 주소에만 바인딩되어 있으면 포워딩 규칙이 있어도 접속이 실패할 수 있다.

---

## 💬 한 문장으로 설명하면

> 포트 포워딩은 VM, 컨테이너 또는 사설 네트워크 안의 서버에 접근할 수 있도록, 바깥쪽의 주소와 포트를 실제 서버의 주소와 포트에 연결하는 네트워크 안내 규칙이다.
